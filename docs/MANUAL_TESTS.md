# Acceptance checklist: two employees and one guest

Use a staging deployment with HTTPS/WSS. Use Chrome/Edge on one network, Firefox or Safari on a second device/network, and a mobile external guest on cellular data. Use headphones to prevent feedback. Never use the automated test accounts or local secrets in production.

1. Create the first admin with the CLI. Add employee A and employee B through People. Confirm B cannot access Settings/People APIs (403) or manage A's meetings.
2. A schedules a meeting. Confirm the invitation opens with an automatically created link, username and masked password. Copy the complete invitation and send it to B and the guest. Confirm times, show/hide password, email-app draft and copied text. Reschedule and confirm the same credentials remain; Schedule again must create new credentials.
3. B and the guest open the same link in separate browsers. Wrong username/password must fail; the correct credentials open pre-join. Enter distinct names and confirm distinct identities. A link alone must not grant access. Neither guest can read host-only sharing details or use workspace/admin endpoints. Check optional email invitations separately with real SMTP; emails must include the credentials and correct calendar time.
4. Test camera preview, microphone level, and speaker tone. Choose a second camera/microphone where available. Deny permissions, then restore permissions using browser site settings. Join with both devices off and independently enable each later. Check actual audible speech and visible movement in both directions.
5. Confirm B and guest wait without entering the media room. A admits B, denies the guest and confirms that same-session re-entry is blocked. For the remaining checks, use a fresh browser context and admit the guest. A new browser can request entry with shared credentials; admission is not identity verification. Confirm no host controls appear for B/guest, and direct moderation API calls fail.
6. Test participant grid, active-speaker highlight, screen-sharing stage, audio during screen sharing, device switching, chat in both directions, and hand raise/lower. Check keyboard focus, labels, and screen-reader navigation.
7. Host mutes the guest. Confirm the guest can intentionally unmute but no host action enables their mic/camera. Remove the guest; both a fresh token request and a signaling connection through the gateway with an earlier token must fail. Confirm raw port 7880 is inaccessible from the Internet.
8. Lock the room. Already connected participants remain; a fresh or refreshed join fails. Unlock, then rejoin. Refresh an admitted guest and confirm the same identity/admission returns.
9. Disconnect A's network for 10 seconds, then restore it. Others must remain in the room. Repeat for the guest. Confirm reconnect status, no duplicate permanent identity, and a usable Rejoin screen on terminal failure. Repeat under bandwidth throttling and packet loss; verify adaptive media quality.
10. Disable UDP in a controlled test network to force ICE/TCP. Then use a restrictive network requiring TURN/TLS on TCP 443. Verify the selected ICE candidate pair in browser WebRTC diagnostics. Do not infer TURN success merely from a normal LAN call.
11. Move the scheduled end close to now in a dedicated test meeting. Confirm the communicated 30-minute allowance and automatic removal at the deadline (up to 15 seconds later). Explicit End for everyone must disconnect B and the guest, and further joins must fail.
12. Toggle Arabic on desktop and 390px mobile layouts. Confirm RTL navigation/forms/chat and readable mixed Arabic/email content. Test the device's browser keyboard and portrait/landscape camera controls. Return to English.
13. In Admin settings, upload a PNG logo/favicon. Reject SVG, spoofed files and oversized images. Change the support address, duration and invitation policies; verify backend enforcement. Enable SMTP and reminder settings only after configuring credentials server-side. Observe a real reminder arriving.
14. Confirm no record button and no false recording link. The post-call view must report an unrecorded meeting. No recording file is expected in this release.
15. Restart services during a disposable meeting; verify a recoverable error/rejoin experience. Run backup, restore into a separate staging volume and verify sign-in, invitation decrypt/resend, settings and assets. Check disk space and logs.

## Automated browser suite

Run the local frontend, backend and LiveKit first. Seed local-only disposable test accounts with `scripts/seed_test_accounts.py`, then run `npm run test:e2e`. The Playwright suite uses separate isolated Chromium browser contexts for host, employee and guest, and synthetic camera/microphone sources. It verifies actual remote video decoding and live remote audio tracks. It does not prove physical microphone fidelity, speakers, a second network, mobile hardware, production TURN or production TLS.

Generated screenshots and HTML reports are under ignored `test-results/` and `playwright-report/`. Tracing is disabled to avoid recording invitation tokens or authentication payloads. Treat failure screenshots as private because an invitation form could be visible.
